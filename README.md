# 卫戍协议 · 赛事直播 UI（WardenBroadcast）

《明日方舟：卫戍协议》赛事用的直播包装与控制台。一套程序同时提供**导播控制台**和**透明叠加层**：控制台切队、切人、改计时，OBS 里的浏览器源实时跟着变。

> 非官方项目，与鹰角网络 / Hypergryph 无关。《明日方舟》相关名称与素材版权归原权利方所有；本仓库不含任何官方美术资源，UI 中的头像与画面均为占位素材。

---

## 1. 它能做什么

| 模块 | 能力 |
| --- | --- |
| 赛事信息 | 赛事名、赛段、轮次/对阵，顶带常显 |
| 队伍与选手 | 两队各 4 人；队名、昵称、头像、存活/已淘汰、在线/Offline 独立维护 |
| 焦点切换 | 点选手卡片任意位置切到该选手画面；Offline 选手不可切换 |
| 转场 | 切人时主画面弹出选手卡 + MD3 循环进度 + 心电波形，约 3 秒掩盖拉流重连 |
| 计时 | 服务端权威正计时；开始/暂停/继续/重置；刷新、重连、OBS 重载后自动恢复 |
| 解说 | 1–2 名解说的姓名与头像，压在左下栏，不遮挡主画面 |
| 主题色 | 6 套 MD3 预设 + 自定义取色，整套界面按 Material 3 令牌重算 |
| 背景 | 自定义背景图，自动裁切压缩 + 缩略图预览，只铺边框不挡画面 |
| OBS 集成 | 场景切换、开始/停止推流、一键生成 8 路媒体源、焦点自动显隐 |
| 直播信号 | 手机用 B 站 App 开播 → 填房间号 → 自动代理成 FLV 供 OBS 拉流 |
| 模拟源 | 没有真实推流时，一键给 8 名选手建模拟画面，用于彩排与验证 |

## 2. 画面版式（1920×1080 基准）

```
┌───────────────────────────────────────────────┬──────────┐
│ 顶带 0,0 1920×90                               │          │
├───────────────────────────────────────┬───────┤  右栏    │
│                                       │       │ x=1440   │
│        游戏区 0,90 1440×810            │       │ 宽 480   │
│        严格 16:9，由 OBS 采集源填充      │       │ 当前队伍 │
│                                       │       │ 4 名选手 │
├───────────────────────────────────────┴───────┤          │

└───────────────────────────────────────────────┴──────────┘
```

- 叠加层按 `min(w/1920, h/1080)` 等比缩放，1280×720 下版式与字号层级完全不变，不会重排；
- 游戏区背景默认**透明**（黑场可切），给 OBS 下面的游戏采集让位；
- 背景图用 `clip-path` 只铺顶带、右栏、解说栏。

## 3. 安装

### 3.1 安装版（推荐）

1. 运行 `WardenBroadcast-0.1.0-x64.msi`（未签名，首次会弹 SmartScreen → 更多信息 → 仍要运行）；
2. 开始菜单启动 **WardenBroadcast**；
3. 若提示「无法访问 Windows Installer 服务」：管理员 CMD 执行 `net start msiserver` 后重装。

数据位置：`%APPDATA%\WardenBroadcast\match-data\`（`state.json` + `assets\` + `logs\main.log`）。

### 3.2 便携版

1. 解压 `WardenBroadcast-0.1.0-x64-portable.zip` 到任意目录；
2. 双击 **`start.cmd`**（或 `启动.cmd`）——**不要直接双击 exe**；
3. 数据落在同目录 `userdata\`，整个文件夹可拷走。

`start.cmd` 里的两个参数不是可选项：

```
WardenBroadcast.exe --no-sandbox --user-data-dir="%~dp0userdata"
```

- `--no-sandbox`：Chromium 沙箱在部分机器上初始化失败会直接退出（异常码 `0x80000003`）；
- `--user-data-dir`：把 Crashpad 与配置写到程序目录，避开 `%APPDATA%` 被重定向/管控的环境。

### 3.3 源码

```bash
npm install
npm run dev        # vite 开发服务器（控制台 + 叠加层热更新）
npm run build      # 构建 dist（前端）+ dist-server/server.cjs（服务端）
npm run start      # 起服务并打开控制台
```

环境：Node.js ≥ 20，Windows 10/11 x64。

## 4. 第一次启动

程序首次打开是**初始化向导**，按顺序填：

1. 赛事名 / 赛段 / 轮次（例：明日方舟：卫戍协议 · 季后赛 · 半决赛）；
2. A 队、B 队队名（纯文字）；
3. 每队 4 名选手：昵称、头像（PNG/JPEG）、初始状态；
4. 解说 1–2 人：姓名、头像；
5. 比赛计时初始值（正计时，从 00:00:00 起累加；需要倒计时口径时把"设定时长"当作上限自行控制，程序不做加时）。

填完点「进入控制台」，之后所有信息都能在 **设置** 里改。

## 5. OBS 接入

### 5.1 叠加层浏览器源

1. 来源 → `+` → **浏览器**；
2. 宽 `1920`、高 `1080`、FPS `60`；
3. URL：`http://127.0.0.1:7317/overlay.html`（端口被占用时会自动顺延 7318/7319/7320，控制台"直播叠加层预览"里有**复制地址**按钮，以那里为准）；
4. 勾选「关闭源时关闭」不必开；叠加层背景本身透明，可直接叠在游戏采集之上。

> 叠加层是**网页**，不是窗口。用「窗口采集」永远选不到它，只能用「浏览器」源。

### 5.2 WebSocket（场景 / 推流控制）

1. OBS → 工具 → **WebSocket 服务器设置**；
2. 勾选「启用 WebSocket 服务器」，端口 `4455`，记下密码（或点"显示连接信息"）；
3. 控制台 → 设置 → **OBS 连接**：地址 `ws://127.0.0.1:4455`，填密码，点连接。

密码只存在内存里，**不会落盘、不会随仓库发布**；程序也不会替你打开 OBS 服务或关闭认证。

> 连不上且报 `4009 Authentication failed`：多半是 OBS 被强杀过，配置没落盘。让 OBS 正常退出一次（菜单退出，不是任务管理器结束），配置会写回 `config.json`，再启动即可。

### 5.3 媒体源（真实推流）

手机端用 B 站 App 开播（不需要 5000 粉，第三方推流码才需要）：

1. 控制台 → 设置 → **直播信号源**，在对应选手行填房间号（3–12 位数字）；
2. 点 **生成 / 更新 8 路媒体源**，OBS 的「比赛画面」场景里会出现 `SRC-A1 … SRC-B4`，全部 `ffmpeg_source`；
3. 切人时只启用焦点那一路，其余自动关闭。

内部链路：`/stream/<选手ID>.flv` → 服务端取 B 站 `playUrl` → 带 `Referer` 转发 FLV。签名 60 分钟过期，代理会在剩 5 分钟时后台换签，**不切断已有连接**（切断会导致 OBS 重连丢 SPS/PPS 而花屏/绿屏）。

### 5.4 模拟源（没有真实推流时）

设置 → OBS 连接 → **生成模拟源**：给 8 名选手各建一个 `SIM-*` 浏览器源，画面是队伍色心电波形 + 昵称 + "模拟画面 · 非真实推流"角标，位置与真实源一致（0,90 / 1440×810）。

用途：彩排、验收切人、检查构图，不消耗任何带宽。**它不会验证真实 FLV 解码链路**。

## 6. 控制台结构

```
┌───────────── 比赛信息（只读摘要 + 设置） ─────────────┬────── 比赛计时 ──────┐
│                                                      │  00:12:35  开始/暂停 │
├───────────── 当前队伍与播出焦点 ────────────────────┼─── 叠加层预览 ──────┤
│ [A][B] 队名         每行：头像·昵称·存活·在线         │  iframe + 地址复制   │
└──────────────────────────────────────────────────────┴──────────────────────┘
```

- 左侧选手行**整卡可点**：点空白处切画面，点状态按钮只改状态（不误触切人）；
- 设置弹窗五个页签：比赛信息 / 直播信号源 / 画面与素材 / 主题色 / OBS 连接；
- 深链接 `http://127.0.0.1:7317/?settings=1` 直接打开设置。

## 7. 计时说明

- 状态机：`idle → running ⇄ paused`，到点不停（正计时，无加时）；
- 服务端只存 `startedAt` 与 `accumulatedMs`，剩余/已过时间由客户端用 `Date.now()` + 时钟偏移本地换算，**不逐秒累加**，所以刷新、断线重连、OBS 重载浏览器源都不会漂移；
- 控制台与叠加层读同一份快照，显示的秒数一致。

## 9. 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 双击 exe 没反应 | 用 `start.cmd`；直接双击缺 `--no-sandbox` / `--user-data-dir` |
| 端口被占用 | 程序自动顺延 7318–7320；旧实例残留会先被探测并复用 |
| OBS 看不到叠加层 | 用「浏览器」源，不是「窗口采集」 |
| 画面是黑的 | 设置 → 画面与素材 → 画面底色切成「完全透明」 |
| 画面偏绿 | OBS 设置 → 高级 → 色彩范围设 Partial（有限），色彩空间 709；硬件解码关掉 |
| 延迟 10 秒以上 | 媒体源 `buffering_mb` 过大；本项目默认 1MB + `-fflags nobuffer`，改过则恢复 |
| 画面糊 | 瓶颈在手机端码率与 OBS 缩放：输出 1920×1080、8000kbps、缩放过滤器 Lanczos |
| 头像不显示 | 先确认素材表已同步（本版已修）；仍空则清除浏览器缓存重开叠加层 |

## 11. 构建安装包

```bash
npm run build

export ELECTRON_BUILDER_CACHE="$(pwd)/.ecache"
export TEMP="$(pwd)/.temp" TMP="$(pwd)/.temp"

# 便携目录 + 手动压缩
npx electron-builder --win dir --x64 -c.electronDist="$(pwd)/node_modules/electron/dist"

# MSI
npx electron-builder --win msi --x64 -c.electronDist="$(pwd)/node_modules/electron/dist"
```

三个环境变量缺一不可：缓存与 TEMP 都要指到工作区内（WiX 解包与 electron 缓存写入 `%APPDATA%` 会失败），`electronDist` 指向本地 electron 避免联网下载。`build.msi.additionalLightArgs: ["-sval"]` 已写在 `package.json`，用于跳过被组策略禁用的 ICE 校验。
